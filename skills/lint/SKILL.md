# Lint the wiki

The third operation of the LLM Wiki pattern (Andrej Karpathy's idea of a knowledge base an
LLM keeps): **ingest** adds, **query** reads, **lint** keeps the compiled layer honest.

This skill runs the vault's own lint script and works through what it finds. It does not
carry its own list of checks: what counts as a finding is whatever the vault's schema file
and the script say. It assumes a vault laid out like this, and says so when it is not:

```
<vault>/
  schema.md        what a page must look like (frontmatter fields, link rules)
  wiki/            the compiled pages the lint reads
  wiki/index.md    a catalogue of pages, regenerated by the script
  wiki/log.md      one dated bullet per change
  raw/             source documents, never edited
  <lint script>    reports findings (--report), rebuilds the index (--fix-index)
```

Name the lint command once in the vault's instructions file (for example
`LINT_CMD: python3 tools/wiki-lint.py`); the steps below write it as `<lint command>`.
If no lint script exists, say so and stop; do not write one inside this skill.
The `librarian` skill in this collection has a small read-only checker for orphans, thin
pages and duplicates that works on any Markdown folder.

## Steps

1. From the vault root (the folder holding `schema.md`), run the report:

   ```bash
   <lint command> --report
   ```

   This step is mechanical and can go to a small worker model: it runs the command and
   returns the counts per report heading and each finding with its file and line. Done when
   the counts it returns match the report's own totals. Steps 2 to 5 stay in the main
   session.

2. Read the report. Group what it found by the headings the report itself uses, and say in a
   few lines what is there. Numbers, not impressions. Add the judgement checks a script
   cannot make, clearly labelled as leads: contradictions between pages, concepts mentioned
   in several pages that have no page of their own, missing cross-links.

3. Propose the fixes as a short list and **wait for a yes** before editing anything. Apply
   only what was approved. Rules while fixing:
   - A `description` is one sentence compressed from the page's own opening, never invented.
   - Repair a broken link, or link an orphan from a related page. Never delete an orphan.
   - Never rewrite the text of a claim the user has marked as checked (for example with
     `(✓)`).
   - Never edit anything under `raw/`, and never hand a confidential folder to a subagent.
   - Never edit the lint script to make a finding go away.

4. If pages were added, renamed or given new descriptions, regenerate the index:

   ```bash
   <lint command> --fix-index
   ```

5. Run the report once more, then append a bullet to `wiki/log.md` under today's date
   heading, starting with **Lint** and stating what changed, with counts.

## What this skill never does

- Decide what a page means, or resolve a contradiction between two claims by picking one.
  Both stay, with a line naming the conflict, until the user or a source settles it.
- Invent a `description`, a date or a source.
- Lint `raw/` or any folder the vault marks as confidential or archived.
